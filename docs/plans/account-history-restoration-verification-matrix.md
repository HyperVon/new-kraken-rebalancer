The parent review and independent read-only reviewer tracks covered accounting/exchange, persistence/recovery, backend API/UI, and frontend/docs/code generation. Four earlier findings were fixed: expired cached asset metadata can no longer authorize trading after refresh failure, intraday holdings CSV neutralizes formula-leading reason text, refreshed SVG chart markers retain exact intraday selection times, and identity lookup failures cannot publish a full-account row under an unverified account scope. Gate 7 now passes the measured browser fixture; only the OS-process restart and termination subchecks in gates 6 and 10 are permanently deferred.

## Scope and policy notes

- The implementation does not hard-code STRC. Any ledger checkpoint whose Kraken asset class is `equity` is excluded from daily balances, totals, holdings, filters, and daily exports. All USD ledger changes remain cash.
- The rebalancer now reads Kraken's public `/public/Assets` metadata before configured non-USD ticker pricing and permits only an explicit `currency` class. Configured `equity`, `tokenized_asset`, unknown, or missing metadata fails the cycle before ticker pricing and order planning; unconfigured symbols such as STRC and AAPL remain outside the allocation allowlist. No ticker-name heuristic or stock-specific exception was added, and allocation/trade math is unchanged. The balance API still lacks a per-balance generic `equity` class, so this boundary conservatively fails closed when the supported metadata contract cannot establish eligibility. History uses imported ledger `assetClass=equity` to exclude stock-share balances while retaining every USD ledger movement.
- Authenticated runtime sync was not tested. The browser fixture uses a fake account and local exchange service. No production environment was touched.
- The private database's imported trades/ledgers extend farther back than this calculation. This run proves the latest 365 completed days only; it does not claim all-time daily values.
- The plan's §1 directs agents not to modify agent skills automatically. The legacy History boundary remains in `.agents/skills/trade-history-sync/SKILL.md`, `.agents/skills/frontend-js-development/SKILL.md`, and `.agents/skills/ktor-html-views/SKILL.md`; those instructions still conflict with this plan's replacement contract. This implementation follows the newer user-approved plan and leaves those skill files unchanged as directed.
