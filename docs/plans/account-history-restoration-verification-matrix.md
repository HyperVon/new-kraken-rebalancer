## Scope and policy notes

- The implementation does not hard-code STRC. Any ledger checkpoint whose Kraken asset class is `equity` is excluded from daily balances, totals, holdings, filters, and daily exports. All USD ledger changes remain cash.
- The rebalancer's production calculation and execution code were not changed. Its configured-allocation allowlist ignores unconfigured asset keys, including arbitrary stock symbols such as STRC and AAPL; the focused test covers those two examples. This does not classify assets by equity share class. A user-configured stock ticker remains **NOT VERIFIED** as excluded: Kraken documents `/private/Balance` as a map of asset identifiers to amounts (including `.T` tokenized-asset suffixes), while `/public/Assets` currently documents `currency` and `tokenized_asset` (`xStocks`) as its available `aclass` choices; neither contract exposes the imported ledger's generic `assetClass=equity` on each balance entry. No safe generic equity classification is available at the current analyzer boundary. History uses the imported ledger's generic `assetClass=equity` classification to exclude all stock share balances and retain all USD ledger changes.
- Authenticated runtime sync was not tested. The browser fixture uses a fake account and local exchange service. No production environment was touched.
- The private database's imported trades/ledgers extend farther back than this calculation. This run proves the latest 365 completed days only; it does not claim all-time daily values.
- The plan's §1 directs agents not to modify agent skills automatically. The legacy History boundary remains in `.agents/skills/trade-history-sync/SKILL.md`, `.agents/skills/frontend-js-development/SKILL.md`, and `.agents/skills/ktor-html-views/SKILL.md`; those instructions still conflict with this plan's replacement contract. This implementation follows the newer user-approved plan and leaves those skill files unchanged as directed.
